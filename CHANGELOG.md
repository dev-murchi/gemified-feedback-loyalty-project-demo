# Changelog

All notable changes to this project are recorded here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). There are no releases yet; entries reference backlog items in `docs/08-sprint-0-backlog.md`.

## [Unreleased]

### Added

- S0-01: Project scaffolded with the NestJS 12 CLI as an ESM project on Node.js 22 and TypeScript 6.0.
- S0-01: Quality gates: TypeScript strict with four extra flags; ESLint with typescript-eslint (complexity ≤ 9 and the size rules of `docs/07` §8); Prettier; dependency-cruiser with five layer and context rules; Vitest with unit, contract, integration and e2e projects and an 80 % line coverage gate on domain and application code.
- S0-01: Empty API entry point (`src/main.api.ts`) and composition root (`src/composition/app.module.ts`), with an e2e test that boots the application.
- S0-01: Docker Compose for PostgreSQL 14 and Redis 7.2 (`noeviction`).
- S0-01: GitHub Actions workflow running every quality gate and `npm audit --audit-level=high`.
- `ARCHITECTURE.md` and this changelog.
- S0-02: API contract lint with Redocly CLI (`npm run contract:lint`, also in CI and `verify`).
- S0-02: Prism mock server for the API contract (`docker compose --profile mock up -d mock`) and a smoke check that calls all 12 endpoints (`npm run contract:mock:check`).
- S0-03: Shared kernel: `Result` with `map`/`andThen`, branded typed ids (`UserId`, `BrandId`, `BranchId`, `FeedbackId`), `Clock` and `IdGenerator` ports, `DomainEvent`, `DomainError`, `ConcurrencyConflict`, `AggregateRoot`, the `UnitOfWork` port with event routing and outbox records.
- S0-03: `InMemoryUnitOfWork` and `InMemoryTable`: synchronous event handlers in the same unit of work, outbox records for outbox-routed events, full rollback on any failure; `SystemClock`, `RandomIdGenerator`; test support `FakeClock` and `SequentialIdGenerator`.
- S0-03: dependency-cruiser rule `core-does-not-use-shared-adapters`; coverage gate now includes the shared kernel.
- S0-04: Catalog context: `Brand`, `Branch` with `QrCode` entities, `LabelSet`; `QrToken` generated from 16 bytes of an injected `RandomSource` (FR-QR-01); `RevokeQrCode`; `QrResolver` and `LabelSetProvider` open host services (unknown, revoked or malformed tokens give `QR_INVALID`, FR-QR-02); in-memory repositories.
- S0-04: Repository contract tests: a generic `versionedRepositoryContract` (version 0 insert, save twice, stale conflict, rollback) used by the Brand, Branch and LabelSet contracts, run against the in-memory adapters; Catalog test builders in `test/support/`.
- S0-04: Shared kernel: `markSaved` key, `RandomSource` port with `CryptoRandomSource`, `saveVersioned` for in-memory repositories, `retryOnConflict`; `Brand` type helper renamed to `Branded`.
- S0-04: Demo catalog (2 brands, 10 branches, S-4 label sets) under `src/catalog/adapters/inbound/demo/`, with a re-runnable snapshot generator (`npm run demo:snapshot`, `tsx`); loaded by the composition root only with `DEMO_DATA=true`, and startup fails with `NODE_ENV=production`. dependency-cruiser rule `demo-data-only-from-composition`.
- S0-04: Composition: `PersistenceModule` (shared in-memory store and unit of work) and `CatalogModule`, generated with the Nest CLI and wired with factory providers.
- S0-06: Gamification context: publishers' event contracts `UserRegistered` and `FeedbackValidated` (types only); `Wallet` with an append-only ledger (`reward:{feedbackId}`, room for `clawback:`), `xpTotalAfter` and earning date = `submittedAt`; `LevelPolicy` and `RewardAmounts` (validated); `OpenWallet` (deliberately not idempotent), `AwardReward`, `GetWallet`, `RewardLookup`; in-memory wallet repository with its contract and the TC-GAM-04 property test (`fast-check`).
- S0-06: `EventRouter` (typed keys, frozen after registration, refuses lookups before freeze); routes registered only in `src/composition/event-routes.ts`; start-up fails if the routes were never frozen. `Logger` port with `ConsoleLogger` and the `RecordingLogger` test fake.

- S0-05: Identity context: `User` with `DeviceKey` entities (trust level follows only from the attestation result, `revokeDeviceKey`, `checkKeyUsable`); single-use 60-second challenges with an in-memory store capped at 10 000 waiting challenges (a full store answers `429 RATE_LIMITED` with `Retry-After`).
- S0-05: `RegisterDevice` (single-use nonce, platform check outside the transaction, a known key returns the existing user, concurrent registration retried), `CreateSession`, `AuthenticateRequest`; `DevAttestationVerifier` and `DevSessionProofVerifier` (real P-256/ES256 proof of possession; refuse `NODE_ENV=production`).
- S0-05: ES256 access tokens (`jose` 6.2.12, 15 minutes, `kid`), signing key from `JWT_PRIVATE_KEY` and `JWT_KEY_ID` (generated outside production, required in production).
- S0-05: Shared HTTP platform in `src/platform/http/`: Problem Details with `code` and `requestId`, one error-code to HTTP-status table kept equal to the contract by a test, `X-Request-Id`, 8 KB JSON limit, bearer guard over an `Authenticator` abstraction, request validation with Zod 4.6.7; `X-Powered-By` disabled.
- S0-05: `POST /v1/auth/challenge`, `/register`, `/session` and `GET /v1/me/wallet`; Identity reaches the wallet through its own `SessionWalletReader`, answered by Gamification's `WalletReader` in the composition root.
- S0-05: e2e tests over real HTTP (TC-AUTH-01, 02, 03, 04, 06, 08, 09; user and wallet in one transaction; error responses leak no internals, T-I7); every e2e response is checked against `docs/api/openapi.yaml` (Redocly bundle, `ajv` 8.20.0 and `ajv-formats` 3.0.1 as devDependencies).
- S0-07: Feedback domain: `RewardCooldown` (one pending feedback per user and branch, 24 hours between rewards counted from the rewarded feedback's submission, at most 3 attempts in any 24 hours as a sliding log), `FeedbackText` (control characters other than tab and line breaks removed, NFC, 20–1 000 code points), `IdempotencyKey`, `RequestFingerprint`, and the `Feedback` aggregate (leaves `analyzing` once; reward eligibility fixed at submission; raw text kept for 2 years).
- S0-07: Raw comments are envelope-encrypted with AES-256-GCM: a data key per comment, the feedback id as context, and a local master key from `RAW_TEXT_KEY` and `RAW_TEXT_KEY_ID` (generated outside production, required in production). An unreadable ciphertext throws `RawTextUnreadableError` (500).
- S0-07: `SubmitFeedback` (a repeated request gets the first answer, even after the QR code was revoked; a reused key with a different body is `IDEMPOTENCY_KEY_MISMATCH`; the QR code, the proof and the encryption are handled before the transaction), `GetFeedbackStatus` (other users', unknown and malformed ids all answer 404), `ApplyAnalysisResult` and `FinalizeUnanalyzedFeedback` (24-hour close, SRS CR-007); in-memory feedback repository with its contract and the sweeper query.
- S0-07: Open host services: `BranchDirectory` and the QR code id in `ResolvedQr` (Catalog), `PlatformProofVerifier` with `DevRequestProofVerifier` (Identity; the proof covers SHA-256(`Idempotency-Key` ‖ raw body), made with the session's still-active device key), and the `UnanalyzedReport` contract (Analysis, implemented in S0-08).
- S0-07: `POST /v1/feedbacks` and `GET /v1/feedbacks/{feedbackId}`; event routes `FeedbackSubmitted` → outbox and `FeedbackAnalyzed` → `ApplyAnalysisResult`; every entry point creates the app with `HTTP_APP_OPTIONS`, which keeps the raw body; rejected QR tokens are logged (TC-QR-07). e2e tests cover TC-QR-01, 06, 07, 10, TC-API-01, TC-API-02 and the whole reward path over HTTP.
- S0-08: Analysis domain: AI-free `PreChecks` (gibberish only when there is no letter, or one character is more than a configurable 60 % of the letters, digits and emoji; owner decision A), `PiiMasker` (SDD 8.6: phone, e-mail, plate, TCKN with check digits, IBAN, card with Luhn; names stay, TZ-8), `RetryPolicy` (1 minute doubling, at most 1 hour, every attempt before submittedAt + 24 h), and the `FeedbackAnalysis` aggregate (one result with model, prompt and label-set versions and token counts, FR-AI-11; failure kind `provider_unavailable` or `invalid_response`); in-memory repository with its contract.
- S0-08: `ProcessAnalysisJob` (deadline and "still analyzing" checked first, so a closed or duplicate job costs no LLM call; LLM call outside the transaction; result and `FeedbackAnalyzed` in one unit of work with the reward), `parseLlmOutput` (exactly four fields, five sentiments, a topic of the current label set), `ReportUnanalyzed` (a reward only after `provider_unavailable` with the budget guard off; `NoBudgetGuard` in the demo), and Feedback's `RawTextSource`. `FeedbackAnalyzed.sentiment` and `topicKey` are null for pre-check spam.
- S0-08: `OpenAiSentimentAnalyzer` (Chat Completions with a strict JSON schema over `fetch`; network errors, timeouts, 408/409/429, 5xx and an unreadable 200 body are `unavailable`; other error statuses throw; request and response bodies are never logged) and the prompt `feedback-analysis/v1`. `LLM_DRIVER` chooses `openai` or the demo `fake`, which refuses `NODE_ENV=production`; `OPENAI_API_KEY`, `OPENAI_MODEL`, `OPENAI_BASE_URL`.
- S0-08: `AnalysisModule`; e2e tests from HTTP submission through the job to the reward, with the demo stand-in and with the OpenAI adapter against a local fake provider. TC-AI-01 is covered by the length rejections at submission (TC-API-02) and the "rejected requests store nothing" tests.
- S0-09: Insights domain: `TimeRange` (ISO 8601 date or date-time with offset; Europe/Istanbul by default; impossible dates and date-times rejected; canonical zone names; the first real instant of a day across DST changes), keyset `Cursor` and `KeyCursor`, `PageSize`, `Scope`, the complaint rule and `tally` (summary counts), `REPORTABLE_STATUSES` (valid and unanalyzed; spam never).
- S0-09: `B2bClient` (`ClientId`, `SecretHash`, scopes, required expiry, revocation), `IssueB2bToken` (RFC 6749 errors; an unknown or malformed client id is checked against a decoy hash; an absent or empty scope means all of the client's scopes), `ScryptSecretHasher` (`node:crypto`), B2B access tokens with their own ES256 key (`B2B_JWT_PRIVATE_KEY`, `B2B_JWT_KEY_ID`) and `aud: "b2b"`.
- S0-09: `ReportingQueries` (read-only, bound to one brand; the in-memory version in `composition/`) and `ListBranches`, `ListBrandFeedbacks`, `GetBranchSummary`, `GetHeatmap`, `ListTopics`; another brand's branch is 404.
- S0-09: `POST /v1/b2b/oauth/token` and the five `/v1/b2b/*` GET endpoints; `ClientAuthGuard` with per-route scopes (401, 403) in `platform/http`; demo clients from `B2B_DEMO_CLIENTS` (needs `DEMO_DATA=true`, refused in production).
- S0-09: Audit log (FR-B2B-09): every B2B call that passed the guard is written before its response, scope denials and cross-brand 404 probes included (0 records); a failed audit write fails the request. The token endpoint is not audited.

### Changed

- The e2e contract checker closes an `allOf` as a whole (`unevaluatedProperties: false`) instead of each branch, so `Topic` plus `count` is accepted while extra fields are still rejected. `configureHttp` also parses `application/x-www-form-urlencoded` (8 KB) for the OAuth2 token endpoint.
- SRS v1.6, SDD v1.3, threat model v1.1, `docs/04` v1.4, `docs/06` v1.2, `docs/07` v1.13, API contract 0.2.6-demo and 0.2.7-demo: CR-007 ambiguity review (24-hour rule, off-schema LLM answers never rewarded, deletion leaves the ledger untouched, the proof also covers the Idempotency-Key, reject vs. low trust, control characters, the OAuth2 error format exception, demo gaps for Must requirements and test traceability).
- API contract 0.2.5-demo: `X-Platform-Proof` documents the development-mode proof (ASN.1 DER ES256 over SHA-256(`Idempotency-Key` ‖ raw body bytes), signed with the device key `dk`); the proof binds the body and the key, and a reward needs normal trust plus a valid proof. No field or code changes.
- `docs/07` v1.12: the unique key-identifier constraint (`device_keys_key_identifier_uq`) joins the ledger key as the second constraint mapped to a concurrency conflict.
- `CLAUDE.md` working mode: routine technical choices are decided and listed; the owner is asked about money and points, security and personal data, and customer-visible behaviour. `docs/08` S0-10 records the challenge-flooding risk.
- Bounded contexts moved to `src/contexts/<context>/` (shared kernel, platform and composition stay beside them); every dependency rule rewritten and re-proven; new rule `platform-imports-no-context`. `docs/07` v1.11.
- API contract 0.2.2-demo: `RegisterRequest` and `SessionRequest.keyId` descriptions document the development-mode content (encodings, signed bytes, DER signatures, `"format":"dev"`); no field, type or endpoint changes.
- API contract 0.2.3-demo: `/v1/auth/register` verifies key possession on every registration, also for an already registered key; an invalid signature is `401 SIGNATURE_INVALID` and a revoked key `403 KEY_REVOKED` (descriptions, responses and examples only; no field or code changes).
- API contract 0.2.4-demo: `SessionRequest.assertion` and `signature` document the development-mode signature (ASN.1 DER ES256 over SHA-256(nonce), raw r‖s rejected); an unknown `keyId` answers like an invalid signature; `KEY_REVOKED` is reported after the signature is verified. The dev stand-in has no iOS sign counter (TC-AUTH-05 is outside the demo subset); no field or code changes.
- Published event types are defined in the publisher's `domain/events/` (`UserRegistered`, `FeedbackValidated`); `public/` only re-exports them. dependency-cruiser rule `domain-events-only-shared-kernel`. `docs/06` v1.1, `docs/07` v1.10.
- `docs/07` v1.9: adapters log through the shared-kernel `Logger` port; no personal data in log fields; tests use the `RecordingLogger` fake.
- `docs/07` v1.8 and `docs/08`: context-specific access keys (`*-access.ts`) with the `context-access-only-in-domain-and-outbound` rule; event routes are registered only in `src/composition/event-routes.ts` and frozen afterwards; the `UserRegistered` → `OpenWallet` wiring moves back into S0-06.
- SDD v1.2 (development-time change, S0-06): `LEDGER_ENTRIES.xp_total_after` stores the total XP after each entry, so a feedback's level-up (FR-GAM-05) is derived from a fact that never changes; references to SDD v1.1 updated.
- `docs/07` v1.7: only the ledger idempotency-key constraint, matched by name, becomes `ConcurrencyConflictError`; every other unique violation stays an infrastructure error. `docs/08` S0-11: the PostgreSQL adapter maps only that named constraint.
- `docs/08`: S0-06 (Gamification) now comes before S0-05 (Identity), owner decision: every user has a wallet from the moment they exist. S0-06 writes the publishers' event contracts first (`UserRegistered`, `FeedbackValidated`, types only); `/v1/me/wallet` and the user + wallet transaction test move to S0-05.
- S0-04 review: concurrency conflicts are thrown (`ConcurrencyConflictError`) and roll back the unit of work; `retryOnConflict` reruns the whole unit of work once and rethrows a second conflict; repository `save` returns `Promise<void>`. New contract case: a conflict on a later save undoes earlier saves.
- S0-04 review: `Branch` copies QR code dates in and out; revoking an already revoked code returns ok and stores nothing; the demo loader validates snapshot ids; loader and generator refuse snapshot entries without a definition.
- `docs/07` v1.6: conflicts are thrown and roll back the unit of work; decisions before the first save; no general try/catch inside a unit of work.
- `docs/07` v1.5: version 0 rule (never-stored aggregate; insert when there is no row), `adapters/inbound/demo/` folder and `demo-data-only-from-composition` rule.
- `docs/07` v1.4: domain code is grouped by aggregate (`domain/<aggregate>/`), use cases live in `application/use-cases/`.
- Shared kernel review fixes: an aggregate's recorded events can only be taken with the `takeEvents` key from `src/shared-kernel/repository-access.ts` (replaces the public `pullEvents()`), and dependency-cruiser rule `repository-access-only-in-outbound-adapters` limits that import to outbound repository adapters. `InMemoryTable` deep-copies rows on write and read, so changing a saved or loaded object no longer changes stored state.
- `docs/07` v1.3: `takeEvents` key and `repository-access-only-in-outbound-adapters` rule; in-memory tables copy rows, rows are plain data (checked by repository contract tests); after a successful save the repository sets the instance's version to the stored version (`markSaved`, implemented in S0-04).
- `docs/07` v1.2: `shared-kernel/adapters/` and `test/support/` folders, `core-does-not-use-shared-adapters` rule.
- API contract 0.2.1-demo: description for the `Cüzdan` tag. No endpoint or schema changes.
- `docs/07` v1.1 and `docs/04` v1.3: Vitest replaces Jest; `docs/07` adds the `shared-kernel-is-pure` dependency rule.
